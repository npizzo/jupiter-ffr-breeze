# Efficient continuation of the matched 512² runs

Continue the completed forced/unforced pair from their own t=200 checkpoints to t=400, on Unity. Preserve the 2π-periodic horizontal box, f=1, beta=0, 512² grid, centered second-order advection, RK3, dt=0.0025, ordinary viscosity 0.0001 and zero drag. The instability coefficient remains 0.0002 in 12≤|k|≤16 excluding k_x=0, versus zero in the control.

The original custom operator consumed 82–84% of runtime and allocated about 226 MB per timestep. This driver uses native ScalarDiffusivity for ordinary viscosity. For the forced case it computes native corner vorticity directly into a reusable complex array, combines the instability multiplier and inverse discrete Laplacian in Fourier space, and recovers face tendencies from the streamfunction. Two preplanned in-place transforms replace four allocating transforms. The unforced case performs no transforms in the callback. The model's pressure solve remains unchanged. No change to physical forcing, resolution or timestep is used to obtain the speedup.

Release checks compare the mature-state trajectories after 30 steps to the original driver (relative velocity error <1e-10), verify serialized split/restarted trajectories at the same tolerance, measure warmed performance on the same node (at least 3× faster in both cases), and require at least 90% reduction in total timestep allocation. The custom callback must allocate less than 64 KiB. These are short implementation and performance checks, not additional scientific experiments or a resolution comparison.

Each case uses one CPU and 4 GB in a single continuation job, avoiding repeated compilation. Checkpoints every 10 model time units; vorticity every 0.5. Internal wall limit 90 minutes, scheduler limit two hours; a partial result retains its checkpoint and reports failure instead of silently releasing dependent jobs. Finite-state and CFL<0.5 checks remain at each RK stage. Raw fields and all computation stay on Unity. Original source and t≤200 output are retained.
